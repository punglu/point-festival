# CC 적용 가이드 — 가족 플랫폼 디자인 패키지

## 이 패키지가 무엇인가
승인된 UI/UX를 코드에 반영하기 위한 참조 자료 모음입니다. **디자인 시안이며, 그대로 갈아끼우는 파일이 아닙니다.**
기존 프로덕트 코드베이스, 컴포넌트 구조, 상태관리, 라우팅을 그대로 유지한 채, 이 안의 시각 규격(색/타이포/스페이싱/래디우스/레이아웃 치수)만 참고해 반영해 주세요.

## 폴더 구성
```
가족 플랫폼 화면 재현.dc.html          모바일 71개 화면 전체 (실제 값 인라인)
가족 플랫폼 화면 재현-tokenized.html   위와 동일 화면, 값이 var(--token)으로 치환된 비교본
가족 플랫폼 화면 재현-tablet.dc.html   태블릿 반응형 71개 화면 (가로 1024×700 + 세로 768×1024, 화면당 2뷰)
design-system/                        스타일가이드 HTML + canonical-tokens.css/json + 10종 MD 문서
design_handoff_family_platform/       위 파일들의 사본 + 반응형 요약이 포함된 README
uploads/                              브랜드 로고 등 실제 에셋
support.js                            프리뷰 런타임 (프로덕션에 포함하지 말 것)
```

## 적용 우선순위 (유연하게, 단계적으로)
1. **먼저 토큰만 도입.** `design-system/canonical-tokens.css`를 프로젝트 전역 스타일 진입점에 추가(또는 기존 :root 토큰과 매핑). 이 CSS는 새 값을 강제하지 않습니다 — `TOKEN_CLASSIFICATION.md`를 보고 기존 디자인 토큰과 이름이 겹치거나 의미가 같은 게 있으면 기존 이름을 우선하고 alias만 추가하세요.
2. **화면 단위로 점진 반영.** 71개 화면을 한 번에 안 옮겨도 됩니다. 우선순위 화면(홈/포인트/할일/앨범/채팅 등 핵심 15개, `design_handoff_family_platform/README.md`의 "Responsive — Tablet" 절 참고)부터 컴포넌트화하고 나머지는 필요할 때 순서대로.
3. **레이아웃 치수는 참고값이지 고정값이 아님.** 실제 브레이크포인트, 그리드 시스템, 컴포넌트 라이브러리가 이미 있다면 그 규칙을 우선하고, 이 파일의 padding/gap/radius 수치는 근사치로 대응하세요 (`COMPONENT_STYLE_CONTRACT.md`가 상태별 규칙을 문서화함).
4. **모르는 부분은 반드시 물어보고 진행.** `AMBIGUITY_AND_PM_REVIEW.md`에 PM이 이미 확정한 8개 항목과 근거가 있습니다 — 임의로 새 해석을 만들지 말고 이 문서 기준을 따르세요.

## 절대 하지 말 것
- 기존 상태관리/데이터 모델/API 계약을 이 시안에 맞춰 바꾸지 말 것 (시안은 화면 예시일 뿐 데이터 스키마 근거 아님)
- `design-system/*.md`에 "screen-local"로 분류된 값(예: 포인트 잔치 진행바 그라데이션)을 전역 토큰으로 승격하지 말 것
- 임시 이니셜 아바타(서/민/아빠 등 텍스트)나 placeholder 사진 배경을 실제 자산인 것처럼 하드코딩하지 말 것 — 실제 이미지 자산은 별도 작업으로 교체 예정

## 남은 작업 (사용자 측)
- 인물 아바타·채팅/앨범 사진의 실제 이미지 교체는 사용자가 사진 자료를 제공해야 진행 가능. 그 전까지는 이니셜 아바타 + placeholder 패턴 유지.
