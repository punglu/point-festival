NAS Container Manager 활성화

DSM 7.x 기준. DS218+는 공식 Docker 지원 모델입니다.

설치 방법

  • DSM 로그인 → 패키지 센터 → 검색: Container Manager
  • 설치 후 Container Manager 열기
  • 좌측 메뉴 프로젝트 확인 (Docker Compose 지원)
💡 DS218+는 Intel Celeron J3355 CPU로 Docker를 공식 지원합니다. ARM 기반 모델(DS220j 등)과 달리 모든 일반 이미지 사용 가능합니다.

NAS에 프로젝트 파일 업로드

NAS에 폴더 생성

File Station에서 다음 경로에 폴더를 만드세요:

/volume1/docker/mc-points/

업로드할 파일 구조

/volume1/docker/mc-points/
  docker-compose.yml
  nginx/
    nginx.conf
  api/
    Dockerfile
    package.json
    server.js
  data/               ← SQLite DB 저장 (자동 생성됨)
  public/
    firebase-compat.js
    index.html
    admin.html      ← import 1줄 수정됨
    user.html       ← import 1줄 수정됨
    styles.css
  db_backup/
    mark-point-festivals-default-rtdb-export.json
  scripts/
    import-db.js

업로드 방법

  • Synology Drive로 폴더 동기화 (권장)
  • File Station에서 직접 업로드
  • SCP: scp -r nas-deploy/ admin@192.168.x.x:/volume1/docker/mc-points/
⚠️ admin.html, user.html은 nas-deploy/public/ 폴더 안에 있는 수정된 버전을 사용하세요. 원본 public/ 폴더의 파일이 아닙니다.
3
Firebase 데이터 → SQLite 마이그레이션

NAS에 SSH 접속 후 마이그레이션 스크립트를 실행합니다.

① SSH 활성화 (DSM)

DSM → 제어판 → 터미널 및 SNMP → SSH 서비스 활성화 (포트 22)

② SSH 접속

# 터미널에서
ssh admin@192.168.1.xxx   # NAS IP 주소

③ Node.js 임시 설치 (마이그레이션 스크립트 실행용)

# NAS SSH에서
cd /volume1/docker/mc-points

# Docker로 Node.js를 임시 실행해서 마이그레이션
docker run --rm \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/db_backup:/app/db_backup \
  -v $(pwd)/scripts:/app/scripts \
  -v $(pwd)/api/package.json:/app/package.json \
  -w /app \
  node:18-alpine \
  sh -c "apk add python3 make g++ && npm install better-sqlite3 && node scripts/import-db.js"
✅ 성공 시 data/app.db 파일이 생성됩니다. ls -lh data/로 확인하세요.

Docker 컨테이너 빌드 & 시작

방법 A — Container Manager GUI (권장)

  • Container Manager → 프로젝트 → 만들기
  • 프로젝트 이름: mc-points
  • 경로: /volume1/docker/mc-points
  • 다음 → 완료
  • 자동으로 빌드 & 시작됩니다

방법 B — SSH 커맨드

cd /volume1/docker/mc-points
docker compose up --build -d

# 로그 확인
docker compose logs -f

시작 확인

# 컨테이너 상태
docker compose ps

# 예상 출력:
NAME              STATUS    PORTS
mc_points_web     Up        0.0.0.0:8080->80/tcp
mc_points_api     Up        (내부 3000번)
💡 최초 빌드는 5~10분 소요됩니다 (better-sqlite3 native 컴파일). 이후 재시작은 30초 이내.
5
내부(LAN) 접근 테스트

브라우저에서 접속

http://192.168.1.xxx:8080         # 메인 페이지
http://192.168.1.xxx:8080/user.html  # 아이들 페이지
http://192.168.1.xxx:8080/admin.html # 관리자 페이지

확인 체크리스트

  • ☐ 메인 페이지 정상 로드
  • ☐ 기존 플레이어 데이터 표시 (Firebase에서 가져온 데이터)
  • ☐ 관리자 모드에서 퀘스트 추가 → 실시간으로 user.html에 반영
  • ☐ 포인트 수정 → 즉시 반영
  • ☐ 두 기기에서 동시 접속 → 한쪽 변경이 다른 쪽에 즉시 표시
🔍 브라우저 개발자도구 → 콘솔에 [firebase-compat] Socket.io 연결됨 메시지가 보이면 정상입니다.
6
DDNS + 포트포워딩 설정 (외부 접근)

① Synology DDNS 설정

  • DSM → 제어판 → 외부 액세스 → DDNS
  • 추가 클릭
  • 서비스 제공업체: Synology (무료, xxxx.synology.me)
  • 호스트 이름 입력 → 등록
  • 상태가 정상으로 표시되면 완료

② 공유기 포트포워딩

공유기 관리 페이지(보통 192.168.1.1)에서 설정:

외부 포트내부 IP내부 포트설명
80192.168.1.xxx (NAS)8080웹 서비스

③ 외부 접속 테스트

http://your-name.synology.me/
http://your-name.synology.me/user.html
🔒 보안 권고: 가족용 서비스이므로 admin.html에는 간단한 비밀번호 보호를 추가하는 것이 좋습니다. Nginx Basic Auth 또는 앱 레벨 PIN 사용 권장.

HTTPS 설정 (선택, 권장)

DSM → 제어판 → 보안 → 인증서 → Let's Encrypt 인증서 추가

도메인 연결 후 자동으로 HTTPS가 활성화됩니다.

7
Firebase 프로젝트 종료 (선택)

NAS 서비스가 안정적으로 운영되는 것을 확인한 후 Firebase를 정리하세요.

  • Firebase Console → 프로젝트 설정 → 프로젝트 삭제
  • 또는 Realtime Database만 비활성화: 데이터베이스 → 데이터 삭제
  • Firebase Hosting 비활성화: Hosting → 사이트 삭제
💡 Firebase 무료 플랜(Spark)은 비용이 없으므로 당장 삭제하지 않아도 됩니다. NAS 서비스가 1~2주 안정적이면 그때 삭제해도 됩니다.

📊 Firebase vs 자체 호스팅 비교

항목 Firebase (기존) NAS Docker (신규)
실시간 DB Firebase Realtime DB SQLite + Socket.io
호스팅 Firebase Hosting Nginx (Docker)
코드 변경량 - 각 HTML파일 import 1줄만 변경
비용 무료 (Spark 플랜) 전기료 약 5~8W
데이터 위치 Google 서버 (미국/아시아) 우리 집 NAS
인터넷 없을 때 ❌ 접속 불가 ✅ LAN 내부는 동작
데이터 백업 자동 data/app.db 파일 복사

DB 백업 방법

SQLite는 단일 파일(data/app.db)이라 백업이 매우 간단합니다.

# NAS SSH에서 - 수동 백업
cp /volume1/docker/mc-points/data/app.db \
   /volume1/docker/mc-points/data/app_backup_$(date +%Y%m%d).db
